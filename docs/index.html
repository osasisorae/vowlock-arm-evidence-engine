The experiment

One changed variable.

  1. Freeze the comparison.
    Same Qwen2.5 1.5B Q4_0 file and hash, pinned llama.cpp, four threads, prompt/generation sizes and Arm64 runner class.
  2. Change KleidiAI only.
    Build once with GGML_CPU_KLEIDIAI=OFF and once with it enabled.
  3. Prove the backend.
    The optimized log must select the CPU_KLEIDIAI buffer and I8MM kernels; the baseline must not.
  4. Measure and replicate.
    Runs 4–6 executed the identical commit. Every run produced the same direction: a small prompt gain and a generation regression.
  5. Verify output separately.
    Run 7 requires both runtimes to produce exactly READY and rejects equal-but-wrong outputs.
Why it matters

Optimization needs an evidence trail.

Small local models can make private Setup Companion guidance possible where connectivity, specialist support and compute are limited. But enabling an accelerated backend is not evidence that the user experience improved. This repository is a reusable pattern for Arm developers: verify selection, compare fact-equivalent conditions, preserve raw evidence, replicate, and keep regressions visible.

Claim boundary: the one-token contract is an equivalence canary. It does not establish that free-form device guidance is factual, safe or useful. Peak process memory was not independently measured.
